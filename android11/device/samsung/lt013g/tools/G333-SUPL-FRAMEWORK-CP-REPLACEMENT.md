# Samsung SM-T311 G333 — SUPL previous framework CP session replacement

G332 local-vs-framework Broadcom BCM4752 SUPL link lock was not sufficient for all CP session transitions. Two software defects were identified from the actual gps_proxy.c source.

1. v398_defer_agps_request() clears g_v398_framework_data_open on a replacement REQUEST, but only tracked previous g_v398_local_data_open. A previously successful framework-owned CP OPEN could remain open when the next request entered the local Broadcom SUPL path. G333 now carries g_v398_pending_close for EITHER actual local or framework-owned opened CP session; a merely requested but never opened framework network must not spuriously send CLOSED.
2. v332_framework_data_conn_open() checked local_active and pending_close, but did not retire an already opened framework-owned CP connection on repeated data_conn_open/APN/IP-type handover. G333 closes the prior CP session before replacing it; if CLOSED fails, the new OPEN is refused and cleanup remains pending. An old failed framework CLOSED/FAILED callback also left data_open=false WITHOUT tracking that legacy CP may still have the previously opened session. G333 records pending_close on such failures, and drains it before any new OPEN, keeping the original negative error.

All CP OPEN/CLOSED/FAILED ordering remains serialized with g_v398_link_lock. No new Broadcom command types, no user location manipulation, no fake satellite fix, no modem/RIL behavior modifications, and no global SELinux loosening.
