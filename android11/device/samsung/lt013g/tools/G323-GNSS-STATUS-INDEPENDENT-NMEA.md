# G323 — Android GNSS satellite status independent from optional raw NMEA listener

Android 11 can register GNSS satellite status callbacks independently of raw text NMEA callbacks. The G322 `gps_proxy.c::LT013G_CB_NMEA` dispatch incorrectly enclosed GPGSV/GLGSV and GP/GL/GNGSA parsing in `if (callbacks->nmea_cb && ...)`. An active session whose raw NMEA listener was unset could therefore lose all satellite status notifications even when `callbacks->gnss_sv_status_cb` was registered.

G323 splits the listeners: incoming bridge NMEA packets are accounted unconditionally, GPS+GLONASS GSV/GSA parse only when an active session and GNSS status callback are present, and the optional raw NMEA callback gets the original/corrected sentence when registered. It retains native SV precedence (5-second freshness), physical GPS/GLONASS SVID mapping, GSA used-in-fix handling, 1024-week RMC output correction and AOSP NTP assistance from the prior G316 sources. The change does **not** synthesize position fixes or enable new GNSS constellations.

The new `tools/test_g323_gnss_callback_dispatch.py` compiles the **actual C switch case extracted from gps_proxy.c**, not a hand-retyped approximation. It passes four distinct callback/session configurations with `cc -std=gnu11 -O2 -Wall -Wextra -Werror`. Older host tests of real NMEA parsing/native freshness also passed (`g314_nmea_host_test`). Android 11 HAL compile and `m target-files-package` PASS.

The signed G323 combined OTA replaces exactly one payload from G322: `SYSTEM/vendor/lib/hw/gps.default.so` (new SHA e2a056d95319fe5adaba7c4e7747b77f94eb218049f230878fdcd5f1a450acca). The other five GNSS/SELinux/init files are G316/G322-identical and BOOT is the same G321 kernel. It retains proper TWRP system-as-root paths, old SELinux inode-label preservation (zero `selabel` reassignment), checks exact old G301 SYSTEM+BOOT SHA, and writes BOOT only after six new SYSTEM hashes. Isolated signed updater failure scenarios PASS. No physical install or Enforcing validation yet; further acceptance requires native status callbacks on hardware, correct UTC injection, stable outdoor GPS+GLONASS fix, SMS ACK and phone audio.
