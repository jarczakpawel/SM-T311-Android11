# SM-T311 G331 — SUPL repeated REQUEST without RELEASE

Android11 GNSS proxy on SM-T311 bridges the 2014 Broadcom GPS API25 AGPS callbacks. G330 already serialized deferred local SUPL CLOSED and OPEN against network-generation races. Further source audit exposed a separate case: v398_defer_agps_request() incremented the generation and unconditionally reset g_v398_local_data_open to zero. When Broadcom emitted two REQUESTs without an intervening RELEASE, it lost track of the first open CP connection. The subsequent worker could send OPEN on top of the previous open SUPL session.

G331 production fix: before clearing g_v398_local_data_open on replacement REQUEST, set g_v398_pending_close if the previous local connection was actually open. The pre-existing G330 link lock drains pending CLOSED before opening a new session. If closing old CP state fails, skip the new local OPEN and use the normal Android framework SUPL fallback. Wire protocol, cell radio, Broadcom proprietary blobs, NMEA output, UTC injection and SMS/RIL handling remain unchanged.

New tools/test_g331_supl_duplicate_request.py extracts and compiles real source C functions v398_local_close_worker, v398_agps_request_worker and v398_defer_agps_request with -std=gnu11 -O2 -Wall -Wextra -Werror -pthread and a synchronous mock of only pthread_create. Eight PASS scenarios: the six G330 worker transitions plus consecutive REQUEST without RELEASE requiring OPEN,CLOSED,OPEN, and failure to CLOSE suppressing a second OPEN and invoking framework fallback. These tests do not speak to an actual SUPL server or Broadcom receiver.
