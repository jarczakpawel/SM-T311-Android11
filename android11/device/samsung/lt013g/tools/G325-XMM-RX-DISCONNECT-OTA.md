# SM-T311 G325 — quiesce modem RX submit workers before USB disconnect

Kernel commit `35639917a` closes the remaining HSIC receive quiescence race: `xmm_runtime_disconnect` had called `usb_kill_urb()` before cancelling independent RX submission and RX buffer allocation/retry workers. A concurrently scheduled USB resubmit could therefore race with the kill when modem interfaces are unplugged or re-enumerated. The disconnect handler now marks `present=false/suspended=true`, synchronously cancels BOTH workers, then kills the final receive URB; it subsequently stops the RX parse work and frees buffers. This matches the suspend sequencing repaired in G321. Stock SIPC4 protocol, modem request/ack semantics, Samsung RIL and all audio routes are unchanged.

Full Linux6.12.112 ARM32 `zImage dtbs` build PASS. The five existing tests of the real SIPC4 kernel parsing functions PASS. Actual modem disconnect/reconnect and SMS ACK still require a user-led physical test.

The signed G325 cumulative TWRP ZIP embeds the new G325 BOOT and the same six GNSS/SELinux/system-as-root payloads as G324. BOOT header v0, original product ramdisk and SM-T311 appended device tree are preserved. Boot image size is page-aligned and may vary due to kernel compression; the G325 builder checks alignment and range <= 8MiB rather than requiring exactly 6,838,272 bytes. Correct G301 physical BOOT SHA and six G301 SYSTEM SHA must be present, and all six new SYSTEM hashes must verify before BOOT is written last. In recovery the same SYSTEM ext4 is under /system whereas live Android11 mounts it at /. The older TWRP policy does not contain the GPS executable type, so existing inode security.selinux labels are retained with O_TRUNC extraction, never relabeled by TWRP.

Builder: `python3 device/samsung/lt013g/tools/build_g325_combined_twrp_ota.py`. Isolated signed script preflight, bad-BOOT, corrupt-SYS, BOOT-last and idempotence tests: `python3 device/samsung/lt013g/tools/test_g325_combined_offline.py`. Host PASS != physical recovery/SELinux PASS. This ZIP does not intentionally write recovery, EFS or userdata and is not truly power-loss atomic; do not install unattended. G325 supersedes earlier G324 as the sole newest candidate. Full GPS/GLONASS NTP/SUPL/SV, SMS positive ACK and bidirectional calls/audio remain to be physically verified.
