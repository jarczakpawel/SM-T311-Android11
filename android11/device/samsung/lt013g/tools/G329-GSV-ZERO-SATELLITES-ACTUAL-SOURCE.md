# SM-T311 G329 — handle zero-visible-satellite NMEA GSV without stale GNSS status

In G328/G327 GNSS source `v308_gsv_from_nmea()` rejected any checksum-valid GPGSV/GLGSV with `total == 0`. An ordinary NMEA 0183 receiver can report a one-page **`$GPGSV,1,1,00*CS`** or **`$GLGSV,1,1,00*CS`** sentence when the corresponding constellation becomes unavailable. Rejecting it retains that constellation's old completed NMEA satellite snapshot (up to the fallback expiry), even though the receiver explicitly reported ZERO satellites. This can display stale satellites following temporary loss of GPS/GLONASS, especially in car tunnels.

New production source in `gps-v195/gps_proxy.c` accepts **ONLY** `pages=1,page=1,total=0` as a valid empty GSV and requires checksum validation exactly as for non-empty reports. It completes a valid empty per-talker snapshot, setting its constellation's completed SV count to zero. The GNSS status callback includes any OTHER fresh, receiver-reported constellation; if both are empty, it reports zero. The existing native GPS satellite-report 5sec precedence and GSA receiver-authenticated USED_IN_FIX flags are unchanged. This does not create positions, constellation support, fix status, or RF signal measurements. NTP/UTC assist, RMC time correction and SUPL remain unchanged.

New `tools/test_g329_nmea_empty_gsv.py` compiles the **actual live source** GSV+GSA parser C section with mock GNSS callbacks under `cc -std=gnu11 -O2 -Wall -Wextra -Werror`, using valid checksum-generated synthetic NMEA. Six cases PASS: combined GPS+GLONASS status, GPS empty retains GLONASS, GLONASS empty clears last satellite, GLONASS empty retains GPS, invalid empty multi-page ignored, and native-SV freshness precedence/fallback. Previous G314 full GPS+GLONASS GSV+GSA+NMEA rollover host regression and G323 independent callback test PASS.
