# G396 Broadcom GPS: missing SUPL IP must preserve Android11 HIDL callback

2026-10-17. New reproducible code defect and narrowly scoped source change, GPS-FIRST; no live Android/radio/network/BCB/flash changes.

## Source reproduction
Original Samsung/Broadcom gpsd can request SUPL with family=0 and ipaddr=0 during DNS outage. Existing SM-T311 G397 proxy recovers original/cached resolved IPv4 when present and G398 falls back to Android cellular SUPL if its default-network probe fails. When DNS and OEM IP are BOTH unavailable, before G396 the private gps_proxy callback forwarded AGpsStatus.size=sizeof(AGpsStatus), addr.ss_family=AF_UNSPEC(0). Exact Android11 hardware/interfaces/gnss/1.0/default/AGnss.cpp AGnss::statusCb for that size forwards only AF_INET or AF_INET6; AF_UNSPEC emits Invalid ss_family and callback is DROPPED, so intended cellular SUPL fallback is never requested. This is proven as a source path and isolated reproduced harness, NOT a physically recorded SUPL failure on live G379.

Existing Android11 frameworks/base/services/core/jni/com_android_server_location_GnssLocationProvider.cpp convertToIpV4(INADDR_NONE) already returns null Java byte[] rather than a fake address. Java GnssNetworkConnectivityHandler treats null as unknown host, skips host-specific routing and requests NetworkCapability SUPL over cellular. The G396 source change is confined to SM-T311 vendor gps_proxy.c: on BCM4752 type SUPL REQUEST or RELEASE with no original IP and no DNS cache, put JNI-null marker INADDR_NONE into valid AF_INET sockaddr, preserving callback over HIDL1.0. Crucially, reset sentinel to zero before attempting local TCP probe, so 255.255.255.255 is NEVER used as a socket destination or actual SUPL IP. All valid original/cached IPv4 and IPv6, unrelated non-SUPL messages and local-only release behavior remain unchanged. No new APN, modem reset, DNS provider, SELinux broadening, host route, data collection or generic Android HAL modifications.
