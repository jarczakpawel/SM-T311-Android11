## Exact Android11 source cause

`frameworks/opt/telephony/src/java/com/android/internal/telephony/dataconnection/DataConnection.java::setLinkProperties` currently takes the stock Samsung HIDL/RIL `DataCallResponse.getGatewayAddresses()` and adds a default route via the distinct gateway while its sole IPv4 PDP link address has `/32` mask; **the usual directly connected route is just own /32**, not the gateway. AOSP `ConnectivityService.updateRoutes` first adds non-gateway routes, then gateway routes. The default route is rejected (101) if the gateway has no directly connected host route.

Fix in `frameworks/opt/telephony` commit **717c949db**:
- New source method `addLt013gPdpGatewayHostRoute` adds only `RouteInfo.makeHostRoute(gateway, rmnet1)` immediately before the existing default route.
- Guard on exact model `Build.DEVICE=lt013g`, exact modem network iface `rmnet1`, exactly one IPv4 PDP address, IPv4 prefix `/32`, distinct nonzero IPv4 gateway. All other models, `rmnet0`, conventional /24 or any non-32, zero gateway, self-address gateway, IPv6, dual stack or missing address unchanged.
- **No** change to RIL/CP firmware, network APN, default DNS, network types, PDP dial commands, libsec-ril or telephony retry logic. No owner involvement is required for source testing, but physical OTA is deferred for broken reboot-to-recovery (G382 still staged-only).
- No global Android kernel or netd hacks and no route writes while system is online; the bridge path remains fully AOSP route registration.
