# G1499 - SM-T311 Android11 ImageWallpaper surface scaling candidate

Physical prechange G1441 screen is 800x1280 at 58.454701Hz. The image wallpaper is 1920x1920 and SurfaceFlinger marks it CLIENT-composed. 1920x1920 RGBA8888 is 14,745,600 bytes per surface buffer. With square source-preserving 1280x1280 framebuffer it is 6,553,600 bytes, saving 8,192,000 bytes (55.56% pixels) per wallpaper buffer before gralloc alignment. The GL bitmap texture remains the original source image, and no color conversion, filter, driver clocks, BufferQueue counts or timing changes are requested.

AOSP Android11's ImageWallpaperRenderer.reportSurfaceSize normally publishes the full bitmap dimensions to SurfaceHolder.setFixedSize. The G1499 candidate adds pure Java WallpaperSurfaceSizeCalculator, invokes it for square wallpapers only, and caps the square to the LONGEST screen edge as returned by Display.getRealSize. With square1920 and 800x1280, output surface is 1280x1280 and SurfaceFlinger's actual prechange physical crop is [0,0,1200,1920] (LEFT-ALIGNED, not centered) before scaling to 800x1280. With 1280x1280 buffer the equivalent left-aligned crop is [0,0,800,1280]. Both sample normalized horizontal texture U range 0.0 .. 0.625. The source geometry test also verifies potential centered crop equivalence (0.1875 .. 0.8125), but the physically observed crop mode is left-aligned. Landscape 1280x800 uses the same square buffer. Non-square, smaller, invalid or disabled examples preserve original dimensions. No parallax changed: current Android11 ImageWallpaper.setOffsetNotificationsEnabled(false).

The framework-defined SystemUI bool config_limitSquareImageWallpaperSurface defaults false for all other devices. The device-specific lt013g SystemUI package overlay alone enables it. The standalone Java regression program device/samsung/lt013g/tools/test_g1498_wallpaper_surface.java compiled against actual pure Java helper via javac and passed the geometry, off switch, odd dimensions and rotation tests. This is a focused framebuffer-memory/bandwidth optimization candidate, NOT a measured GPU FPS gain. It may change filtering on the wallpaper at some zoom levels; a physical visual/crop A/B and G1454 swipe frame comparison plus accepted HWC and memory safety checks are required before calling it a real-world improvement.

Graphics sources: https://source.android.com/docs/core/graphics/surfaceflinger-windowmanager and https://developer.android.com/studio/profile/jank-detection .
